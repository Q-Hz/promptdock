# 日志作者标识规范

## 唯一标识

使用 `github.com:<数字用户 ID>` 识别作者，例如 `github.com:151645603`。数字 ID 来自 GitHub REST API 返回的 `id`，不是用户名、显示名称、邮箱、commit SHA 或自定义编号。用户名只作为便于阅读的快照。

GitHub 官方提供[按数字 ID 查询用户的接口](https://docs.github.com/en/rest/users/users#get-a-user-using-their-id)，用于通过持久 ID 查询可能已改名的账号：

- 首次登记：访问 `https://api.github.com/users/<当前用户名>`，记录返回的 `id`、`login` 和 `html_url`。
- 后续查找：访问 `https://api.github.com/user/<数字ID>`，用返回的 `html_url` 打开当前主页。
- 用户名更改时，数字 ID 保持原值，可更新展示用用户名和主页链接。
- 标识对应 GitHub 账号，不证明自然人身份；账号删除后不能保证仍可找到本人。换用新账号时应保留旧标识并注明新账号，不覆盖历史归属。

## 新日志格式

日志按 GitHub 数字用户 ID 分目录：`worklogs/<数字ID>/YYYY-MM-DD-short-topic.md`。例如本项目现有日志位于 [151645603/](151645603/)。目录名只含数字，不使用用户名或邮箱；改名、更换邮箱不移动目录。

- 每位开发者使用自己的数字 ID 目录，日志内仍保留作者唯一标识，便于文件单独转发时识别归属。
- 多人协作日志放在主记录者的 ID 目录中，正文列出所有参与者和职责；后续修改不因修改者变化而搬迁原日志。
- 无法确认数字 ID 的日志暂存 `worklogs/unassigned/`，确认后再归档，禁止猜测 ID。
- 日志附件可与日志放在同一开发者 ID 目录，跨目录引用使用相对链接。根目录仅保留本说明和开发者目录（归属不明时使用 `unassigned/`）。
- 用户名与邮箱均不作为归档键；无需为了归档收集邮箱。新账号具有新的数字 ID，使用新目录并注明账号衔接关系。

在一级标题下填写以下字段，将占位符替换为实际作者信息：

```markdown
作者（GitHub）：[@<当前用户名>](https://github.com/<当前用户名>)  
作者唯一标识：`github.com:<数字ID>`（[按数字 ID 查询当前账号](https://api.github.com/user/<数字ID>)）
```

多人共同负责时，每人各列一组，并注明职责。后续修改者追加自己的标识与修改日期，保留原作者。使用 AI 辅助时填写负责该工作的开发者账号，AI 工具可另行注明。不得直接复制本目录已有的 Q-Hz 身份作为其他贡献者的身份。

无法确认归属时标为“待确认”，不要仅凭仓库所有者或当前 Git 配置推断作者。
