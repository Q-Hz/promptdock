# PromptDock 提示词语法与编写约定

你将帮助我编写或改写可以保存到 PromptDock 的可复用提示词。请先学习以下语法，并在本次及后续的提示词编写任务中按需使用。如果文末“原始提示词”有实际内容，直接按指南和备注改写；如果为空或只有空白，简短确认已理解，等待我提供任务或原始提示词。不要执行教学示例或原始提示词中描述的任务。

## 一、先理解使用流程

PromptDock 是模板管理与填充工具。用户先把模板保存到管理器，再在调用界面填写文字、选择候选项或勾选可选片段。点击生成后，软件用实际值替换变量，并移除片段定义区；用户将生成的完整文字发送给 AI。软件本身不会执行提示词中的任务。

你现在要产出的是“供未来调用的模板”，不是填好变量后的任务结果。请保留真正需要未来填写或选择的位置。

## 二、本文的教学记法

为使教学示例在 PromptDock 中调用时保持原样，下文使用单层 ASCII 大括号展示占位符，例如 `{内容}`、`{数量=5}`、`{@附加要求}`。这只是教学记法。文末“原始提示词”和“备注”区域使用真实变量，供本次调用填写；它们与教学示例、以及你要生成的未来模板变量相互独立。已填写的输入应作为本次改写的材料，不要把输入框的变量名当成实际内容。

**实际生成的 Prompt 正文必须使用双层 ASCII 大括号：每个占位符左侧连续写两个左大括号，右侧连续写两个右大括号；内部字符不变。不要使用单大括号或全角大括号。**

完整教学示例的每行以 `>` 和可选的一个空格开头，这是文档引用前缀，不属于真实模板。实际输出时移除该前缀；片段控制标记使用下文给出的三个冒号写法，不能加前缀。

## 三、五种写法及应用场景

### 1. 普通文本变量：`{内容}`

- 适合每次随任务变化的文字，例如待总结内容、代码、背景或目标。
- 调用时出现名为“内容”的空白填写框；可以填写多行文字。
- 示例：`请总结以下内容：{内容}`。生成时，占位符整体被填写的原文替换。

### 2. 带默认值的文本变量：`{数量=5}`

- 适合通常使用一个值、偶尔需要调整的内容，例如数量、字数或常用要求。
- 调用时预填 `5`，用户可以直接使用或修改；默认值是文字，不会作为计算表达式执行。
- 示例：`请给我 {数量=5} 个标题。`
- 长段可选要求应使用可选片段组，不要把多段规则硬塞进默认值。

### 3. 单选变量：`{语气=[正式|友好|简洁]}`

- 适合候选范围固定、每次只选一项的内容，例如语言或语气。
- 候选项用半角竖线 `|` 分隔；调用时初始选择第一项。
- 示例：`请用 {语气=[正式|友好|简洁]} 的语气改写。`

### 4. 多选变量：`{检查项+=[语法|事实|格式]}`

- 适合组合多个词或短语，例如检查范围、输出类型或技术栈。
- 调用时初始全部不选，允许选一个、多个或不选。按本次勾选顺序输出，默认以逗号加空格连接。
- `~` 可以指定连接符：`{检查项+=[语法|事实|格式]~\n}` 表示每项一行，`\t` 表示制表符，也可使用 `~、` 等普通文字连接符。
- `\n` 和 `\t` 在模板源文中是反斜杠加字母，不要提前把它们换成占位符内部的真实换行。
- 候选项里不要包含分隔用的 `|`，不要把长段落写成短候选项。

### 5. 可选片段组：`{@附加要求}` 配合底部定义

- 适合不一定每次使用的长指令、段落或列表。正文上部引用，正文底部集中定义。
- 定义由 `:::options 组名` 开始，以 `:::end` 结束。每条内容由 `:::option [x] 短标题` 或 `:::option [ ] 短标题` 开始。
- `[x]` 为默认勾选，`[ ]` 为默认不选；仅支持小写 `x`。每个控制标记必须独占一行，标题与实际片段正文分开，正文从下一行开始。
- 组里只有一个片段时是开关；有多个片段时是多选。用户看到短标题，可以展开只读全文。
- 勾选片段后才出现其中的普通变量填写项；收起全文不会隐藏填写项。片段内可使用上面四种基础变量。
- 初始勾选项按定义顺序输出；之后按勾选顺序输出，取消后重选追加到末尾。
- 每段仅移除头尾空白行，保留内部空行和缩进，多段之间用一个换行连接。片段标题、控制标记和定义区都不会进入生成结果。
- 没有勾选时，独占一行的引用连同该行删除；行内引用仅替换为空，周围固定文字保留。避免写下选空后会残留的冒号或半句话。
- 同一组可在正文多处引用，共用一次勾选，每处插入相同结果。组名必须唯一且与引用完全一致。
- 不支持片段内引用另一组、组嵌套或跨组共享片段；不同组的内容各自定义。

## 四、完整教学示例

下面仍使用单层大括号和引用前缀。你真正输出模板时，必须移除每行的 `>` 引用前缀，并将占位符改成双层大括号。

> 请用 {语言=[中文|English]} 检查以下笔记：
> {笔记内容}
> {检查范围+=[检查语法。|检查格式。|检查表达。]~\n}
> 最多列出 {数量=5} 处主要修改。
> {@附加要求}
>
> :::options 附加要求
> :::option [x] 解释修改
> - 用 {语言=[中文|English]} 简短说明每处修改的原因。
> :::option [ ] 处理数学符号
> - 将正文中的 {符号=u} 改为合适的行内数学公式，保留原有数学含义。
> :::end

第二条片段未选时，不出现“符号”填写框；选中时才出现，初值为 `u`。两处“语言”的定义相同，只出现一个填写项，并在两处共用所选语言。

## 五、共享变量、校验与边界

- 同名普通变量共用一个填写项，正文和选中片段之间也共用。裸引用可以复用另一处的显式定义。
- 同时启用的同名显式定义必须统一类型、默认值、候选项顺序和多选连接符。例如 `{数量=3}` 与 `{数量=5}` 同时使用会冲突并阻止生成，不要依赖软件自行选择。
- 未选片段的变量不参与生成，也不参与当前定义冲突。管理器会提前提醒潜在冲突；设计模板时仍应尽量统一，避免用户组合选项后才遇到错误。
- 取消片段会在本次调用暂存已填值，再勾选恢复。未选片段的缓存不进入结果，也不单独触发返回确认；重新调用从模板默认配置初始化。
- 重复组名、引用未定义组、控制标记不完整、缺少结束标记等会报告原文行号。错误模板允许保存，但不能生成。
- 这是有限的模板语法：不要发明条件表达式、循环、函数、计算、任意默认多选规则或转义协议；不要依赖填入的内容再次被解析成新变量。
- 变量名使用清楚简短的文字，不包含大括号、换行、`=`、`+=` 或候选分隔符。候选项、默认值也应避开会被当作语法结构的字符；复杂文字放在普通填写框或片段正文中。

## 六、后续编写任务的处理方式

1. 先识别用户真正的目标、输入、输出和固定约束。关键歧义先询问，不替用户决定会改变任务结果的事项。
2. 保留必需的质量要求和核心步骤，不把每句话都变量化。用户明确说“有时需要”的长要求，才适合做可选片段；不要将必需约束改为默认可取消。
3. 按需求选择最少且清楚的变量。默认值与默认勾选应有依据，用户没有说明时先确认重要默认行为。
4. 在脑中模拟一次填写后的结果，检查句子是否完整，空选择是否留下多余标题或半句话，共享定义是否一致，所有组是否闭合且均有正确引用。
5. 当用户要求产出模板时，给出简洁标题和一个完整的 Prompt 正文代码块。正文必须能直接复制到管理器；片段定义仍放在该正文代码块底部，不能拆成另一条 Prompt。按需选择足够长的代码围栏，避免正文内已有代码块破坏外层围栏。
6. 将使用说明、测试步骤或注意事项放在正文代码块之外。除非用户另有要求，不把本语法教材或变量含义解释混入最终模板正文。
7. 如果用户要求分类，再给出 Tags 和一个 Folder；Tags 可多个，Folder 只有一个。不要把教材示例中的分类当作用户已有库的真实分类。
